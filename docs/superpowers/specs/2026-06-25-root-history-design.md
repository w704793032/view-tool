# 根目录历史快速切换设计

## 背景

当前工具只保存一个 `rootDir`。用户需要在多个项目目录之间来回查看时，只能点击“修改”并重新输入绝对路径。这个流程可用，但对高频切换不够顺手。

本设计保留现有单根目录安全模型：服务端任一时刻仍然只有一个当前 `rootDir`，所有文件 API 仍以这个根目录为边界。新增能力只负责记录和切换常用路径，不引入多根目录同时浏览。

## 目标

- 用户可以从工具栏快速切回最近使用过的根目录。
- 成功通过 UI 切换根目录后，路径会持久化到本机 `config.json`。
- 历史列表自动去重，并按最近使用时间排序。
- 无效或已删除的历史路径不会破坏启动和当前浏览流程。
- CLI `--root` 作为临时启动覆盖，不自动写入历史，避免污染列表。

## 非目标

- 不做跨设备同步。
- 不把路径历史提交到 git；`config.json` 仍然是本机私有配置。
- 不同时展示多个根目录，不改变 `/api/tree`、`/api/file`、`/api/raw` 的单根访问模型。
- 不提供复杂的路径管理页面；本次只做工具栏内的轻量切换。

## 用户体验

工具栏保留当前根目录展示和“修改”按钮，并新增“切换”入口：

```text
根目录: D:\projects\a    [切换] [修改]    端口 3000
```

点击“切换”后显示一个下拉面板：

- 第一部分显示置顶路径，如果没有置顶则不显示该分组。
- 第二部分显示最近路径。
- 如果某个路径已经在置顶分组中，最近分组不重复展示它。
- 当前根目录可展示为已选状态，点击不会重复刷新。
- 每个路径项显示短名称和完整路径，完整路径可放在 `title` 中方便悬停查看。
- 路径项可提供“移除”操作，用于清理不存在或不再使用的路径。
- 当前根目录可提供“置顶/取消置顶”操作，让常用路径稳定留在列表顶部。

当用户点击某个历史路径时，前端调用现有切换根目录流程。切换成功后刷新目录树、面包屑和预览区；切换失败时显示错误提示，并保留当前根目录不变。

## 配置结构

在现有 `config.json` 中新增两个字段：

```json
{
  "rootDir": "D:\\projects\\a",
  "recentRoots": [
    "D:\\projects\\a",
    "D:\\projects\\b"
  ],
  "pinnedRoots": [
    "D:\\work"
  ],
  "port": 3000,
  "maxPreviewSize": 5242880,
  "version": 1
}
```

字段规则：

- `recentRoots` 是最近成功切换过的根目录，最新路径在最前。
- `pinnedRoots` 是用户主动置顶的根目录，保持用户选择顺序。
- 两个列表都只保存绝对路径字符串。
- 保存前会先通过 `path.resolve` 规范化，再去重。
- `recentRoots` 默认最多保留 10 条。
- 读取旧配置时，如果字段不存在，按空数组处理。

## 后端设计

`GET /api/config` 返回新增字段：

```json
{
  "rootDir": "D:\\projects\\a",
  "recentRoots": ["D:\\projects\\a"],
  "pinnedRoots": [],
  "version": 1,
  "port": 3000
}
```

`POST /api/config` 保持现有职责：修改当前根目录。成功后：

- 将新根目录写入 `config.rootDir`。
- 将新根目录插入 `recentRoots` 头部。
- 从 `recentRoots` 中移除重复项。
- 截断到最大数量。
- 保存配置并返回更新后的配置。

新增轻量配置端点用于管理列表，不改变当前 `rootDir`：

- `POST /api/roots/pin`，body `{ "rootDir": "<绝对路径>" }`，把路径加入 `pinnedRoots`。
- `POST /api/roots/unpin`，body `{ "rootDir": "<绝对路径>" }`，从 `pinnedRoots` 移除。
- `POST /api/roots/remove`，body `{ "rootDir": "<绝对路径>" }`，从 `recentRoots` 和 `pinnedRoots` 移除。

这些端点只管理配置列表，不改变当前 `rootDir`。为了避免保存明显无效的数据，`pin` 要求目标路径存在且是目录；`unpin` 和 `remove` 可以对不存在的路径执行，方便清理。

## 前端设计

前端状态新增：

- `state.recentRoots`
- `state.pinnedRoots`
- `state.rootMenuOpen`

`loadConfig()` 读取并渲染当前根目录、端口和路径列表。`changeRootDir(newRoot)` 成功后同步更新三个配置字段，并关闭切换面板。

新增工具栏按钮和下拉面板：

- `switchRootBtn` 打开或关闭面板。
- 面板使用现有按钮、toast、modal 风格，避免引入新的复杂组件。
- 点击路径项复用 `changeRootDir(path)`。
- 点击置顶、取消置顶、移除时调用对应 API，然后局部刷新面板数据。
- 点击面板外或按 `Escape` 关闭面板。

## 错误处理

- 历史路径不存在：点击切换时返回 `NOT_FOUND`，前端显示提示，并给用户保留移除入口。
- 历史路径不是目录：返回 `NOT_A_DIRECTORY`，行为同上。
- 配置文件缺少新字段：服务端按空数组补齐，不影响启动。
- 配置文件中包含重复路径：服务端在读取或写入时规范化为去重列表。
- 当前 `rootDir` 无效：继续沿用现有回退到 `process.cwd()` 的逻辑，不把回退路径自动写入历史。

## 测试计划

后端测试：

- `ConfigStore` 读取旧配置时能提供空的 `recentRoots` 和 `pinnedRoots`。
- `POST /api/config` 成功切换后会记录最近路径、去重并限制数量。
- `POST /api/config` 失败时不会写入历史。
- `pin` 只接受存在的目录。
- `unpin` 和 `remove` 可以清理不存在的路径。

前端验证：

- 初次加载能显示当前根目录和历史列表。
- 从历史列表切换根目录后，目录树、面包屑、预览区重置。
- 删除历史项后，下拉面板立即更新。
- 置顶和取消置顶后分组展示正确。
- 点击外部和按 `Escape` 能关闭下拉面板。

## 兼容性

旧版 `config.json` 不需要迁移脚本。新增字段缺失时自动按空数组处理；保存配置后才会写入新字段。

现有 API 路径守卫不需要改变，因为文件浏览仍然围绕单个当前 `rootDir` 展开。
